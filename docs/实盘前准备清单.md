## 2. 第一关：交易时段只读dry-run

维护者准备当日公告文件、复核过的经济条款、最新前收盘输入、相邻交易日历及不可变发布计划。计划必须使用V12子账户昨结净值与自有持仓，不用柜台全账户资产当作V12本金。

核对模拟环境确实是模拟柜台；代码固定8001及策略`v12`不是对柜台真实类型的自动认证。只读无需开写开关，不创建策略账户、不分配资金、不迁移证券。本轮未查询这些部署动作是否已经完成；现场先查现状，不重复开户或划拨。

在交易时段使用`--dry-run`，观察：

1. 子账户身份、现金、已归属份额、可卖量与实际状态一致，手工513300和其他策略证券没有被纳入。
2. 公告覆盖和条款有效；待核更正、缺数据、过期计划会停止并显示原因；普通公告更新不会一律阻塞。
3. 十只ETF当日状态、买卖档、时间戳、价格边界和交易单位能解释。未知状态可以安全等待/停止，不能猜成可成交。
4. 5%触发、整手、现金下限、未决预留和未结算卖款的候选结果符合计划。
5. 模式只使用GET，不进行提交、撤单或refresh。没有实际委托；若公告在运行中失效，不继续保留可用候选。

通过标准：正常数据能形成可解释候选或明确不交易结果；错误数据不会产生可执行假象；账户没有被写入。不要为了让首单出现而篡改目标。

## 3. 第二关：当次授权的一手模拟试单

用户明确指定一只国内ETF、BUY或SELL、稳定授权ID，然后才使用`--trial-send`。**普通`--send`是全计划，绝非一手入口。**

条件：只读检查已通过，模拟策略身份/令牌和归属正确，无需要人工处理的未决订单，指定腿由原计划触发且原交易资格、费用预留、资金/可卖量均允许。买入依赖另一笔未授权的国内卖单时，本次应跳过，不自动卖其他证券。

需要现场确认的结果：

- 只有指定代码、指定方向、最多100份的一笔逻辑订单；没触发或没成交不算软件失败。
- 实际成交价/份额与策略现金、手续费最终确认一致；报告区分业务完成、部分成交和账务对齐。
- 成交后以同一授权再次运行或换输出目录，只查询/收尾，不再新发一笔。
- 若超时或身份不明，停下查原请求；不自行改ID重试。撤单确认之前不释放未知预留。单人维护者可以手工核对并交接。

通过标准：这只ETF在该模拟环境下完成了一个受限流程或正确安全停止。**这不等于QDII与全组合已经现场通过，更不等于实盘放行。**

## 4. 第三关：模拟盘正常日与QDII实际等待路径

后续扩展模拟范围需要另行明确授权，不自动将一手许可扩大到十只ETF或50万元建仓。关注与本策略直接相关的少数路径，不要求刻意制造所有极端情况：

- 国内ETF开盘交易；QDII等待实际复牌后按新报价执行剩余量，不能填回9:30或复牌首价。
- 核实盘中`InstrumentStatus`、`openInt`、`stockStatus`、盘口单位及报价时效。未经确认的47等状态码继续保守处理。
- 14:30停止新单，未决单按真实资格撤单/查询；挂单再临停且撤单不确定时保留身份和预留。确认不了交人处理，不伪报COMPLETE。
- 一笔QDII卖不出，不提前创造卖款、不把其风险当作已消除；其他可交易资产只能使用真正可用的资金，现金下限继续生效。
- 收盘与次日检查现金、应收、份额、可卖量、费用和未决意图，确认模拟柜台未回退/丢记录。异常可安全停机、人工查清，不自动修成“对得上”。

当前柜台适配按最新批准方案：**QDII溢价只记录，不拦截**；卖一相对前收的偏离不得改称同步公允溢价。不在此次上线流程中重新加入旧的5%溢价过滤、自动换基金或参数搜索。

通过标准：实际遇到的正常流程和关键等待/收尾路径可解释；账本对齐；未验证的稀有路径有明确安全停止办法。不要以“跑了固定几天”替代检查，也不强制无限期观察。

## 5. 第四关：实盘环境的最小适配，当前尚未做

`v12/gate/client.py`和`v12/execute.py`目前固定`http://127.0.0.1:8001`和策略`v12`；它们是模拟适配，**当前代码不直接接受8003实盘地址**。

模拟流程通过、用户决定实盘后，再另做一个小范围环境配置变更，而不是全局搜索替换端口：

1. 显式区分模拟/实盘环境、柜台账户、策略身份、令牌来源和资金上限；默认保持模拟，错误环境、账户不一致或未授权写入都拒绝。
2. 确认实盘网关返回契约与模拟一致；试单授权ID、请求ID、运行状态目录要绑定环境和账户，不能跨环境重用。旧模拟状态不得导入真实账户。
3. 读取实际券商费用、可卖量与预留。回测佣金/滑点是研究口径；实际账本按真实成交和费用确认，不再把报价价差或基金内部费用重复扣除。
4. 人工确认V12资金上限与已持仓是否计入50万元，现有513300默认仍属外部手工持仓。与R5重叠的证券沿用网关归属保护，不抢占其他策略持仓，不自动改登记。
5. 保留相同的一手限制和公告复查，再先做实盘只读验证；之后如获明确授权才做实盘小额首单。真实一手通过后，才讨论扩大额度；不是本次commit/push附带的授权。

通过标准：不是“换端口后能连上”，而是无法误连、误用旧授权、误算外部持仓、或在未经批准时发单。若网关契约相同，尽量只改客户端环境与身份绑定，不重写策略和网关。

不必现在增加企业级监控、审批链、灾备平台。邮件为可选项，未接邮件不阻塞手工看报告的试单。要无人值守或后台运行，再单独明确授权和启动方式。
